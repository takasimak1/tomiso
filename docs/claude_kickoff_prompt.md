## 直前までの状況（最終更新: 2026-07-24）

1. **廃棄数入力画面（商品単位）・上代単価フィールド（完了・デプロイ済み / commit d46fc70）**
   クライアントLINE回答により、単品管理ダッシュボードの仕様が確定：
   - 上代＝上代単価（商品マスタ固定値・本部設定）× 合計数量（定価数+値引数+廃棄数）で都度計算。上代達成率＝(定価売上+値引売上)/上代。クライアント検算例と一致確認済み
   - 合計列＝仕込み数（陳列ケース投入数）で確定。過去データ遡及は不要、今後分から記録開始
   - 廃棄数は当初「部門単位」で判断していたが、単品別ドリルダウン（②-1/②-3/③シート）が
     成立しないため**商品単位**に変更（ユーザー判断）
   FileMaker側に `hanbai_API.上代単価`（数値）と新規レイアウト `haiki_API`
   （fk_店舗No/店舗名/売上日/商品名/廃棄数、商品×日付で1レコード）を作成。
   `haiki_entry.php` を新規実装（店舗の取扱商品を部門別一覧表示、廃棄数入力、
   0件に戻すとレコード削除、未来日入力不可）。`top.php`に導線追加。
   実データ相当のcreate/edit/delete一連の動作をテスト店舗(999)で確認済み。
   → 次はダッシュボード本体（pos_API＋haiki_API＋hanbai_APIを突合し、
   エクセルの①〜③の切り口を再現する画面）の設計・実装。

2. **売上日報にととレジ実績列を追加（完了・デプロイ済み / commit 3b88e1a）**
   `daily_report_entry.php` の12時/15時/17時/閉店後の各セクションに、`pos_API`明細を
   `作成情報タイムスタンプ`で時刻カットオフ集計した「ととレジ実績」列（緑色・参照専用）
   を追加。客数はレシート番号のdistinct件数、累計売上は販売金額合計。既存の
   本年入力／前年同曜日と並べて4列グリッドで比較できるようにした。実データ
   （店舗124・07/20付）で表示確認済み。

3. **レシート印刷: 部門小計・バーコード幅拡大（完了・デプロイ済み / commit b34b2b0, dc33e0e）**
   `star_webprnt_inline.php` に部門名行右端の部門小計表示を追加し、バーコード幅を
   width2→width3に拡大。実機試し印刷で小計行の折り返し不具合を発見し、1行の
   文字数上限を48→46に補正して解消。

4. **部門マスタ統一（完了・デプロイ済み / commit 620c716）**
   FileMakerレイアウト `bumon_API`（部門CD/部門名/並び順）を新設し、`bumon_master.php`
   を新規作成。`hq_shohin_maint.php` / `hq_tenpo_maint.php` / `sales_entry.php` /
   `sales_edit.php` / `shohin_maint.php` の部門定義をこのマスタ参照に統一。

5. **インストアコード取得バグ修正（完了・デプロイ済み / commit 620c716）**
   `sales_entry.php` の `_fetch_instore_codes_from_fm()` と `sales_edit.php` の
   `_fetch_instore_codes_from_fm_edit()` が、存在しないメソッド
   `$fm->findRecord(...)` を呼んでいたため、account_API からのインストアコード取得が
   常にサイレントに失敗していた（try/catchで握りつぶされていた）。
   `$fm->findRecords(['query' => [...]])` に修正して解消。
   → 難波店のレシートでバーコードが出ない不具合の原因だった。修正後、印刷・プレビュー
   とも表示確認済み。

6. **UI微修正（完了・デプロイ済み / commit c77bbc1）**
   - `top.php`: ナビボタン「売上登録」→「レジ」に表示変更
   - `sales_entry.php`: レシート画面の「次のお客様へ」ボタンを廃止し、印刷ボタン1つで
     印刷実行と同時に売上登録画面へ戻るよう統合（未使用になった `.rcpt-btn-next` の
     CSSも削除）
   - `sales_entry.php`: 「全消去」「登録する」ボタンに `user-select: none` /
     `-webkit-touch-callout: none` を追加し、タブレット長押し時のコピー/共有メニュー
     表示を抑止

7. **横向きタブレット2カラムレイアウト（完了・デプロイ済み / commit 2d1cf93）**
   `sales_entry.php` のレジ画面に `@media (orientation: landscape)` を追加し、
   左63%（タブ＋商品グリッド）・右37%（カート全高）のCSS Gridレイアウトに変更。
   縦向きは既存レイアウトを完全維持。対象タブレットは実測 23.7cm×14.8cm
   （アスペクト比約1.6、店舗の専用端末のみで使用するため、幅指定ではなく
   `orientation: landscape` のみで判定）。
   **未確認**: 実機タブレットを横向きにして、左に商品ボタン・右にカートが
   意図通り表示されるかの実機確認待ち。
